# 登录用例节奏（§19.7）

安全边界（必须遵守）：
- 用例与对话中**永远不出现凭据明文**；密码等密钥一律经 `secret_get` 现场获取，即取即用。
- `secret_get` / `sms_read` 的返回值只进上下文；引擎会在落盘前把这两类工具结果替换为 `[REDACTED:<provider>:<key>]`。
- 含这两类调用的 run，会话强制不落盘（引擎自动判定，无需记忆）。
- 测试账号（手机号等非密级）可从环境变量 `ASK_TEST_ACCOUNTS` 获取。

## 节奏

1. **先校验已有登录态**：打开 App 后看首页是否已登录（如"我的"页有用户昵称）。已登录 → 跳过全部登录步骤。
2. **识别登录页**：未登录时进"我的"，点登录入口；确认当前页含手机号输入框与登录按钮。
3. **输入账号**：手机号来自 `test_account` 工具（读 `ASK_TEST_ACCOUNTS`）；用 `input` 输入。
4. **取密码**：`secret_get{provider:"<凭据服务>", key:"password"}` → 把返回值直接喂给 `input`（不要复述到任务文本里）。
5. **验证码登录**（若适用）：点"获取验证码" → `sms_read`（引擎会请求敏感操作确认）→ 得到验证码 → `input` 回填 → 点登录。
6. **登录结果确认**：`wait_idle` → `screen` / `uitree` 确认已进入登录后页面（描述可见元素，如用户昵称/头像节点），再 `assert_no_crash`。
7. **收尾**：登录成功后按用例继续；失败则 `ui_dump` 取证并报告，不要反复重试（上限 2 次）。
